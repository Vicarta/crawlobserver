## Required Assertions

- A terminal session is not observable before finalized evidence.
- PR failure never produces terminal `completed` with trusted quality.
- Shared session/revision/predicate counts agree across report and quality.
- 51 eligible / 51 positive gives `pagerank_zero_top_pages=0`.
- A stale positive or negative result is replaced when evidence revision changes.
- A v2 Delta evaluation created before immutable-lineage findings is read as
  stale, publishes one distinct v3 revision, rejects unsafe promotion, and then
  reaches a scheduler fixed point without immutable finding-count collisions.
- A valid Delta v2 on F1 v2 migrates to Delta v3 and remains promotable while
  its exact F1 evaluation and Current Snapshot baseline binding stay on v2.
- Concurrent evaluations never mix findings across revisions.
- Legacy result/findings are imported once into immutable history and remain queryable after repair.
- Concurrent legacy adoption yields one deterministic evidence revision and rejects active PR mutation.
- Findings/evaluation durable plus current-pointer failure leaves the old pointer readable; retry publishes the full new generation.
- Evaluation success plus promotion failure retries promotion without duplicating evaluation.
- Current Snapshot API returns the exact persisted evaluation/evidence/rules/evaluator/baseline binding.
- JS and non-JS session finalization use the same evidence barrier.
- Scheduler replay and process restart are idempotent.
- Historical evaluations select only a strictly older trusted full-crawl
  predecessor by `(started_at, session_id)` and never form cyclic lineage.
- Current Snapshot source and content watermark are monotonic across full-crawl
  and delta replay, fold, restart, and ClickHouse compaction.
- D2 planning on F1+D1 persists D1's watermark/evaluation, F1's raw source
  evaluation, and the exact snapshot revision; replay after applying D2 resolves
  that immutable predecessor from journal history even if current pointers move.
- Missing legacy Delta lineage or a changed predecessor before first promotion
  fails closed with `stale_delta_baseline` before content overlay.
- F1 -> D1 -> D2 -> fold removes D1 raw session/heavy payload from scheduler
  input but retains D1's exact immutable quality/evidence dependency; restart
  replay keeps D2 trusted with the same evaluation and snapshot revisions.
- An unprovable legacy pointer returns 409 and blocks Delta; a newer trusted
  full self-baseline can publish a validated v2 pointer through audited
  `started -> applied` recovery without deleting the legacy audit row.
- If a full pointer is durable but terminal promotion audit is missing, retry
  reuses the original promotion ID, returns the same v2 pointer, and appends
  `applied` without copying content or publishing a new evaluation.
- Delta planning holds the per-project mutation lock from canonical lineage
  capture through candidate reads; promotion cannot enter overlay at the
  deterministic read barrier. Orphan cleanup holds it continuously through
  graph deletion and PageRank finalization.
- Repeated scheduler passes reach a fixed point with no new evaluation,
  promotion, or snapshot revisions after predecessor lineage settles.
- A second `serve`, `gui`, `crawl`, or `migrate` process sharing the state
  directory fails before mutation; owner exit releases the OS lock, and deploy
  never runs explicit migration concurrently with the app or bypasses the
  active-crawl safety gate.
- Viewer/project credentials cannot POST re-evaluate; admin with session access can.
- Production repair does not create a crawl, recompute PageRank, change
  thresholds, edit historical page rows, or restart ClickHouse.
