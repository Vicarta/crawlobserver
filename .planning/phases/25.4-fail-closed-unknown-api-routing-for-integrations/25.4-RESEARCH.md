# Phase 25.4 Research

## Root Cause

`http.ServeMux` treats the registered `GET /` pattern as the fallback for every
otherwise-unmatched GET. The embedded frontend handler does not exclude the
`/api` namespace, so an authenticated typo or missing endpoint is rewritten to
`/` and served as the SPA document.

Authentication rejects the same API request before routing when credentials
are missing, but `http.Error` assigns `text/plain` unless the JSON content type
is set first. The body is JSON-shaped while its media type is not.

## Minimal Change

- In the existing SPA handler, reject path `/api` and prefix `/api/` with the
  existing `writeError` helper before static-file lookup or rewrite.
- In API-key/basic authentication middleware, set `application/json` before
  writing API authentication errors; preserve the Basic challenge for non-API
  browser paths.
- Add focused handler and middleware assertions. No new router, error type,
  storage contract, or compatibility layer is needed.

## Validation Architecture

- Unit: API-key middleware asserts 401 JSON for missing and invalid API keys.
- Server integration: authenticated unknown API GET is 404 JSON, while an
  ordinary unknown frontend route still receives the SPA fallback.
- Existing Current Snapshot and public health tests provide known-route
  coverage; add explicit media-type/status assertions where necessary.
- Repository gate: focused Go tests, `go test ./...`, `go vet ./...`, frontend
  tests/lint/build, then independent code review.
- Production read-only acceptance after a safe app-only restart: exact Current
  Snapshot JSON, unknown API JSON 404, unauthorized JSON 401, health JSON,
  ClickHouse health/`SELECT 1`, and recent error-log review.
