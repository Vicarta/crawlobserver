# Phase 25.4 Context

## Locked Decisions

- Keep `GET /api/projects/{id}/current-snapshot` unchanged and prove it remains
  JSON for an authenticated authorized request.
- Unknown authenticated GET paths at `/api` or below must return a stable JSON
  404 and must never enter the embedded SPA fallback.
- API authentication failures must remain 401 and identify themselves as JSON;
  non-API browser authentication behavior is outside this change.
- Keep `GET /api/health` public and JSON.
- Do not edit SEO Dashboard, Daily Delta, crawler behavior, storage, or existing
  crawl evidence. Do not invoke a live crawl or rescan.
- After tests and independent review, commit and push the owned files, then use
  the existing no-force active-crawl gates for an app-only production rollout.

## Evidence

- The production route exists and returns `200 application/json` at the exact
  normalized Dashboard URL.
- SEO Dashboard normalizes a root base URL to `/api`; the prior diagnostic
  script appended the project path to the unnormalized root and did not execute
  the application connector code.
- Go's `GET /` ServeMux pattern currently catches an authenticated unknown GET
  `/api/...` path. The handler then rewrites it to `/` and serves the SPA index
  as `200 text/html`.

## Acceptance

1. Exact authorized Current Snapshot request remains JSON.
2. Authorized unknown GET `/api/...` returns 404 JSON.
3. Unauthorized API request returns 401 JSON with no HTML response.
4. Public health remains 200 JSON.
5. No crawl, rescan, storage mutation, or Dashboard change occurs.
