# Phase 25.5 Plan 01 Summary

## Delivered

- Replaced interactive username/password authentication with invitation-based
  email identity and single-use six-digit login codes delivered through a
  bounded Resend adapter.
- Preserved existing user IDs, roles, project assignments, API keys, active
  state, and valid cookie sessions. Administrators can assign email addresses
  and issue seven-day invitations to migrate legacy users.
- Enforced 15-minute login codes, replacement and replay protection, five
  failed-attempt invalidation, and 14-day HttpOnly SameSite=Lax sessions with
  Secure cookies on HTTPS deployments.
- Added explicit invitation UI states and password-free user administration.
  Existing programmatic API-key and configured Basic API behavior remains
  separate from the removed interactive password route.
- Added server-only Resend configuration, fake-provider tests, deployment
  examples, and the matching `ProductFeatures.md` contract. Project error
  notification emails remain out of scope.

## Deployment Status

Deployment is intentionally blocked. The read-only production preflight proved
an HTTPS public URL and no active crawl, but both `RESEND_API_KEY` and
`RESEND_FROM` are absent. Restarting would remove interactive password login
without a functioning email delivery path, so no build, restart, live email,
crawl, rescan, publication, or data rewrite was performed.

The remaining action is external configuration: place a valid Resend API key
and verified sender in the production server environment, confirm a still-valid
administrator cookie session, then repeat both no-force safety gates and the
app-only acceptance sequence.
