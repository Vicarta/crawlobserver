# Phase 25.5 Validation Contract

## Automated Gates

- Store tests prove legacy-user migration, normalized uniqueness, seven-day
  invite expiry/replacement/replay, 15-minute code expiry, five-attempt lockout,
  replay prevention, and 14-day sessions.
- Resend HTTP tests prove URL, payload, authorization, User-Agent,
  Idempotency-Key, timeout, non-2xx handling, and redaction with no network call.
- Server handler/routing tests prove generic code requests, invite acceptance,
  admin-only invitation, cookie attributes, existing-session compatibility,
  API-key compatibility, logout, and rejection of the removed password route.
- Frontend component/API tests prove the two-step login, invitation states,
  password-free user management, and accessible loading/error states.
- `go test -race ./internal/apikeys ./internal/server -count=1`
- `go test ./...`
- `go vet ./internal/apikeys ./internal/config ./internal/server`
- `go build ./...`
- Repository frontend test, lint, and production build commands.
- `git diff --check`

## Production Preflight

- `RESEND_API_KEY` and `RESEND_FROM` exist without printing their values.
- Sender domain is verified in Resend.
- `server.public_url` is the intended HTTPS origin.
- A valid current administrator cookie session is available for migration.
- `sudo -n env CHECK_ONLY=1 deploy/restart-app-safe.sh` reports no active crawl.
- Preserve rollback image/source evidence before replacing the app.

## Production Acceptance

After the second no-force safety gate and app-only restart:

- existing administrator session still returns authenticated `/api/auth/me`;
- sending and accepting the administrator migration invite succeeds;
- logout and email-code login produce a 14-day Secure HttpOnly SameSite=Lax
  cookie;
- replayed invite/code and `POST /api/auth/login` are rejected;
- API-key project reads retain their prior authorization behavior;
- `/api/health` is OK, ClickHouse remains healthy with the same container, and
  `SELECT 1` succeeds;
- recent logs contain no unexpected errors and no code/token/secret value;
- no crawl, rescan, recompute, publication, or historical-data rewrite occurs.

If Resend credentials, verified sender, or an active administrator session are
missing, stop before deployment and report the exact prerequisite. Do not keep
or re-enable password login as a workaround.
