# Phase 25.3 Research

## Finding

The production value `2,063` was a count of sitemap publication differences,
not evidence of 2,063 edited pages. Phase 25.2 intentionally compared Fresh to
Published Snapshot and allowed Raw only to label a difference
`pending_unpublished`. Because pending differences stayed actionable, an
untrusted Delta caused the same bulk lastmod reset to be fetched every day.

## Evidence

- Current public sitemap and latest stored raw observation contain 2,088 URLs.
- Relative to Published Snapshot: 2,084 shared, 4 added, 2,059 strictly forward
  lastmods, 25 equal, and 596 old Published URLs removed.
- 1,975 URLs share one 2026-08-15 date cohort; 1,858 share the exact second
  `16:53:17`. This is batch metadata behavior, not an editorial distribution.
- Aug 27 versus Aug 28: all 2,094 joined pages have identical SimHash, status,
  title, and H1; 2,090 have identical ETag and Last-Modified.
- Aug 28 quality is `untrusted · 60` only because candidate coverage is
  99.952107% instead of the configured 100% (`2,087/2,088`). Current Snapshot
  therefore stayed at revision 1.

## Code Cause

- `internal/server/delta_sitemap_selection.go` creates every Fresh-vs-Published
  added/forward event and changes only its source when Raw already observed it.
- `internal/storage/clickhouse_delta.go::LoadDeltaSitemapTerms` returns the
  newest complete Raw and exact Published term, but no per-URL successful raw
  execution/stability evidence.
- `internal/server/handlers_delta.go` launches all selected pending events.
  Conditional validators correctly remain Current Snapshot-bound: using newer
  raw validators would be unsafe because the current `304` overlay retains the
  published representation rather than copying the raw representation.

## Chosen Design

Derive a bounded per-URL stability read model from two immutable completed raw
sessions and feed it into selector revision v2. A matching stable tuple is held
for publication but removed from network execution. Current Snapshot remains
the conditional-request source so a `304` cannot retain the wrong
representation. This adds no schema mutation and keeps failure recovery
deterministic.

## Rejected Shortcuts

- Lowering `max_candidates_per_run`: hides real bulk changes and confuses a
  ceiling with a target.
- Treating any newest Raw observation as consumed: a partial/failed/untrusted
  attempt could hide missing evidence.
- Automatically promoting Raw: violates Current Snapshot quality authority.
- Relaxing 100% coverage: changes quality policy and does not solve perpetual
  retry generically.
- Suppressing identical lastmod cohorts without content proof: can miss a real
  bulk deployment.

## Remaining Risk

The conservative proof needs two completed observations, so it does not avoid
the first attempted fetch of a brand-new bulk timestamp reset. Cohort sampling
before first execution is explicitly deferred rather than silently introduced.
