# Phase 25.3 - Validation Strategy

## Core Invariants

1. Published Snapshot remains the publication and quality authority.
2. Raw stability changes execution only and cannot advance publication lineage.
3. Stability requires two distinct ordered completed observations, the same
   normalized URL+valid lastmod, page coverage in both, and equal nonzero hash.
4. Missing, failed, partial, invalid, cross-project, zero-hash, changed-hash, or
   newer-lastmod evidence remains actionable.
5. `published differences = actionable + stable acknowledged` before caps.
6. Stable acknowledged URLs are neither selected, deferred, nor canaries.
7. Existing caps apply only after actionable classification.
8. Conditional validators remain Current Snapshot-bound; raw evidence cannot
   return `304` while overlay retains a different published representation.
9. Preview is read-only; launch persists exact stability proof lineage.
10. No live crawl/rescan or production historical rewrite is a test or acceptance step.
11. Candidate limits remain upper ceilings: a genuine site-wide change remains
    actionable up to the saved project limits and is not forced toward 50-80 URLs.

## Required Matrix

| Area | Cases |
|---|---|
| Stability storage | two completed fresh sessions; running/stopped/failed; same/different project; same/different origin; full/partial coverage; equal/changed/zero hash; FINAL replacement tie |
| Selector v2 | exact stable tuple; newer raw lastmod; missing/invalid lastmod; added URL; mixed stable/actionable; 0/1/N caps; 50 canaries; deterministic replay |
| Publication | v1 compatibility; v2 stable-only preview; stable plus actionable; deferred actionable; explicit publication hold; stale snapshot revision; no stable evidence may satisfy publication binding |
| Validators | Current Snapshot ETag only; Last-Modified only; both; no validator; exact header bytes; raw evidence cannot change validator source |
| Compatibility | legacy session pair accepted only with exact proof; legacy config without v2 fields; Phase 25.2 response fields preserved |
| UI/API | separate published/actionable/stable/canary/deferred counts; proof lineage; held-publication banner; malformed/legacy states |
| Production fixture | DI-shaped 2,088 sitemap rows, bulk timestamp reset, 2,080+ stable proofs, missing-proof URLs remain actionable |

## Gate Sequence

1. Focused pure selector/config tests.
2. Focused storage tests and required ClickHouse integration fixture when local
   Docker is available; fail explicitly when required and unavailable.
3. Focused server/manager/fetcher tests and race tests for deterministic reads.
4. Full `go test ./...`, changed-package `go vet`, and `go build ./...`.
5. Frontend Vitest, lint, and production build.
6. `git diff --check`, ProductFeatures diff, independent review, commit/push.
7. Production: CHECK_ONLY, app build, CHECK_ONLY, safe app-only restart, health,
   ClickHouse `SELECT 1`, logs, and read-only DI Preview. Never force or start a crawl.
